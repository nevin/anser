## What's new

**The right Node version in every project**
- When you `cd` into a project, Anser switches to the Node version it needs: from `.nvmrc`, `.node-version`, or package.json's `"engines"` (`>=22`, `^20 || ^22`, `18.x`…). It picks from what nvm or fnm installed, keeps your default when it already fits, and switches back when you leave. A `node 22.23` chip shows which one is in use.
- When nothing installed fits, a **Needs Node 24 · Install** chip runs `nvm install 24` in the tab.
- nvm no longer has to load in every shell for this, so you can load it lazily and open new tabs faster.

**Python virtualenvs by themselves**
- A project's `.venv` or `venv` activates when you `cd` in and deactivates when you leave. One you activated yourself is left alone.
- When `pip install` fails with no virtualenv active, an **Install in a new .venv** chip sets one up and installs there.

**Commit from Changed Files**
- Git → Commit… (⇧⌘M), or **Commit…** in Changed Files: write a message, and optionally stage everything, push, and open a pull request on GitHub. It runs in the tab, so you see git's output.
- With AI help on, **Commit with Claude Message…** suggests a one-line message from the diff for you to edit.

**New tabs open instantly**
- Anser keeps one shell ready in the background, so a new tab or split shows its prompt at once instead of waiting for your shell's startup files.

**See-through panels everywhere**
- The task-with-AI panel, Compare, Data and Output viewers, runbooks, forms and What's New use the same blurred, see-through look as the other popups.

**Settings**
- Settings → Suggestions & Helpers: "Use each project's Node version and Python virtualenv".
- Settings → Sessions & Windows: "Keep a shell ready so new tabs and splits open instantly".

## Fixes

- **Closing tabs could freeze Anser.** Closing several busy tabs at once (for example with Close Other Tabs), or a tab printing a lot of output, could leave Anser unresponsive. Fixed in the terminal engine and in the helper that keeps your shells running.
- Help → Report a Problem's startup timings now show how long your shell's startup files take.
